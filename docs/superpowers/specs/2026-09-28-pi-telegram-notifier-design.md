# pi-telegram-notifier — design

## Intent and success criteria

Build a public, independently installable Pi package in `Pi-Plugins/pi-telegram-notifier/`. After each **final** agent response (not intermediate tool-call turns), send a Telegram message containing an ISO 8601 timestamp, the full final text, the provider, and the actual remaining subscription quota or prepaid credit when the provider publishes a documented endpoint usable with Pi's credentials. Never substitute context-window usage or a guess for plan quota. Otherwise say `Quota non disponibile`. OpenRouter credit is explicitly in scope. Do not publish to npm, pi.dev, or GitHub as part of implementation; prepare the repository for subsequent manual publication.

## Package and configuration

The new directory is its own npm/Pi package, separate from `pi-editor-selection`, with the `pi-package` keyword and a Pi extension entry. Read `PI_TELEGRAM_BOT_TOKEN` from the process environment; do not put secrets in project settings, source, logs, examples, or tests. The package is inert until configured and paired. A README explains configuration, pairing, installation from a local or git source, supported provider coverage, limitations, testing, security/privacy, and manual release. Include MIT LICENSE, minimal CI, `.gitignore`, and `AGENTS.md` containing the mandatory principles from `Gybra/software-engineering-principles/AGENTS.md` plus package-specific development/security rules.

## Pairing and delivery

The Pi command `/telegram-pair` initiates or replaces pairing and displays a cryptographically random, one-time code valid for five minutes. During pairing, poll Telegram Bot API `getUpdates` for `/start <code>` from a private chat only. Reject mismatches, group chats, and expired/reused codes. Save only the authorized numeric chat ID in a private user-level file under Pi's agent directory (`PI_CODING_AGENT_DIR`, or Pi's default agent directory). A documented re-pair action replaces the chat. If another process/webhook consumes updates, fail with a helpful message; do not bind an arbitrary chat. Never start a long-lived poller just to load the extension.

Observe Pi's `agent_settled` boundary and extract the final assistant text from the active session branch; skip runs without a completed text response. Send exactly one logical notification for each settled final response (possibly split across Telegram messages for length), regardless of intermediate tool calls/retries. Compose plain-text Telegram messages (no Markdown/HTML injection) and split text beyond Telegram's message size without losing content or breaking Unicode. Network requests have bounded timeouts, and delivery/lookup errors are reported without aborting Pi or leaking token, provider credentials, or response text into logs. The user's response is intentionally sent to Telegram; disclose this privacy consequence in the README. The timestamp is generated when the notification is built (UTC).

## Quota lookup

Resolve the credential for the *actual model/provider used* via Pi's `ctx.modelRegistry` rather than parsing `auth.json`: Pi also supports environment, commands, and OAuth. Use only published provider-specific quota/credit endpoints that expose **remaining** plan allowance or prepaid balance and permit use with that resolved credential; verify the endpoint, auth scheme, unit and response before implementing each integration. OpenRouter's officially documented credits endpoint must be implemented. Inventory Pi's built-in providers and document which expose an applicable endpoint, which have an endpoint but need credentials/scopes not supplied by Pi, and which do not publish an applicable endpoint. Every verifiably usable endpoint in that inventory is in scope, not just OpenRouter. Do not conflate request rate limits, API spend analytics, context usage, or an API-key-specific spending limit with overall subscription quota. If the real remainder is inaccessible (including auth error, missing scope, malformed response, no endpoint, or a custom provider without a known integration), use `Quota non disponibile` and still send the response. No secrets are sent to any destination other than their corresponding official provider endpoint and Telegram Bot API.

## Verification and release boundary

Use offline, behavior-focused tests with stubbed HTTP/Pi events: pairing accepts only the matching private `/start` and expires; final-only delivery including long Unicode text and no completed response; actual provider credit parsing and unavailable fallback; HTTP failures do not stop the agent. Run tests and a package dry run locally. CI runs the same checks. The README records exact provider integrations and limitations, not an unverified blanket claim. Git commit(s) stay local; public GitHub repo, npm publish, and pi.dev listing are separate later release steps requiring explicit user authorization.
